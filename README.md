# 트래픽 분산을 위한 Gunicorn + Uvicorn 마스터 워커 패턴

## FastAPI 서버의 트래픽 분산

동시에 무거운 요청이 많이 들어올 때, 비동기로 처리한다고 하더라도 한개의 프로세스로는 서버가 감당하기 어려울 수 있습니다.

파이썬 프로그램은 기본적으로 한개의 프로세스 당 한개의 코어를 사용합니다. 멀티스레딩 방식으로 구현하더라도 한개의 코어를 넘어서 사용하지 못합니다. 따라서 우리가 구축한 서버 프로그램이 여러 CPU 코어를 점유함으로서 하드웨어 자원을 극한으로 사용하게 하려면 여러개의 서버 프로세스를 동시에 띄워 요청을 분산시키는 멀티 프로세싱 환경을 구축해야 합니다.

그것을 도와주는것이 바로 Gunicorn입니다. 

```
                  [ Client Requests ]
                           │
                           ▼
                  ┌─────────────────┐
                  │  Nginx (Reverse)│
                  └────────┬────────┘
                           │
            ┌──────────────┼──────────────┐ (Unix Domain Socket / TCP)
            ▼              ▼              ▼
      ┌──────────┐   ┌──────────┐   ┌──────────┐
      │ Worker 1 │   │ Worker 2 │   │ Worker 3 │  <-- Uvicorn (FastAPI 실행)  |          |   |          |
      └──────────┘   └──────────┘   └──────────┘
            ▲              ▲              ▲
            └──────────────┼──────────────┘
                           │ (관리 및 모니터링)
                  ┌─────────────────┐
                  │ Gunicorn Master │
                  └─────────────────┘
```

## 마스터-워커 패턴

마스터 프로세스 1개 + 워커 프로세스 n개 조합으로 구동됩니다.

Gunicorn 마스터 프로세스는 여러 프로세스를 띄워 관제하고 들어오는 요청을 순차적으로 분배하고, 죽은 워커 프로세스를 되살려내는 역할을 합니다. 예를 들어 3개 워커 프로세스가 돌아가다가 1개 프로세스가 예기치 못한 오류로 종료되더라도, 마스터 프로세스가 이를 감지하면 새로운 4번째 워커를 부팅하므로 사람이 매번 신경쓰지 않아도 됩니다.

워커 프로세스는 FastAPI 앱이 실제로 실행되는 Uvicorn 서버 프로세스입니다.

## gunicorn 설정 파일

gunicorn 마스터 프로세스에 관한 설정들을 `gunicorn.conf.py`에 작성하고 gunicorn 명령어로 해당 파일을 실행합니다. 요청을 받을 포트, 워커 프로세스 수, 대기 가능 커넥션 수와 타임아웃 시간등을 설정합니다.

## 실행

Gunicorn + Uvicorn 조합으로 프로그래밍된 서버는 아래 명령으로 실행합니다.

```bash
gunicorn main:app -c gunicorn.conf.py
```

도커로 컨테이너화 한다면 아래와 같이 Dockerfile에 추가합니다.

```Dockerfile
CMD ["gunicorn", "main:app", "-c", "gunicorn.conf.py"]
```
